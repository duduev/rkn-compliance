# Инструкции для агентов

Репозиторий содержит скиллы для аудита проектов на соответствие требованиям законодательства РФ.

## Структура

```
skills/<категория>/<имя-скилла>/
├── SKILL.md              обязательно: фронтматтер + инструкция
├── agents/openai.yaml    метаданные для Codex
└── references/           материалы, читаемые по ссылке из SKILL.md
```

Имя папки обязано совпадать с полем `name` во фронтматтере.

## Правила для SKILL.md

- Фронтматтер: `name` (только a-z, 0-9, дефис) и `description`, вместе не более 1024 символов.
- `description` начинается с «Use when…» и описывает **когда** применять скилл, а не что он делает. Описание процесса в этом поле заставляет агента следовать краткой выжимке вместо чтения самого скилла.
- Тяжёлые справочные материалы выносятся в `references/` и читаются по ссылке, а не встраиваются в SKILL.md: он грузится в контекст целиком.

## Правила для скиллов этого репозитория

Скиллы дают инженерные проверки, а не юридические заключения. Поэтому:

- Статус требования ставится только по конкретному файлу и строке, а не по предположению.
- Реквизиты (ИНН, ОГРН, адреса) не выдумываются — запрашиваются у владельца, до ответа остаются плейсхолдеры.
- Действия вне кода (уведомление в РКН, получение ERID) не имитируются, а выносятся в задачи владельцу.
- Любой юридический текст помечается как черновик, требующий проверки юристом.
- Решение, создающее лишь видимость соответствия, не предлагается.

## Перед коммитом

```bash
./scripts/validate-skills.sh
```

Новый скилл дополнительно регистрируется в `.claude-plugin/plugin.json` — валидация это проверяет.
